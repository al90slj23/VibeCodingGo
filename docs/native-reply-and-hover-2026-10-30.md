# 原生回复兼容与可交互任务预览（0.34.1）

## 原生对话为什么报错

本工具原来的桌面输入只发送 type 与 text。Codex owner 会将该 request 保留在当前轮次参数中；原生的对话和标题消费逻辑会直接调用 text_elements.some() 或读取其 length。因此文字已经被接收并执行，原生界面仍可能在渲染阶段抛出 TypeError。

现场原生日志中的 undefined.some 与已安装资源的同一函数、行号吻合。只读检查也发现已完成轮次的缓存参数缺少该数组，而较早的普通轮次有完整数组。任务执行结果 completed / error:null，与本工具的 accepted 回执一致，不能把渲染错误当成消息未发送而重发。

## 修正

DesktopChannel 在实际编码发送前，为普通用户文字构造 text_elements: []，保持文字、消息 ID、目标 owner 及继承设置不变；不修改调用方对象，也不允许调用方注入占位符、图片或额外上下文。

兼容检查仍按方法契约进行。已提交消息只认原来的持久回执，重连、安装与状态刷新不会自动重发。模型、权限、沙箱与账号授权不由这个修复改写。

## 悬停浮窗

浮窗顶部新增带文字的“在 Codex 打开”按钮，直接打开当前预览任务。由当前任务标识绑定回调，隐藏或切换任务后使旧回调失效。

列表先识别指针是否在浮窗内，再识别下面的列表行，避免重叠区域切错目标。离行后有短过渡宽限，移入浮窗立即取消隐藏。状态栏 transient popover 的 delegate 识别自己的可交互浮窗，点击按钮、选择文字或打开文本菜单不会先把父窗口关掉。

文字选择、滚动和跟随最新保留。选区拖动只在真实 mouseDown 生命周期内保持；菜单只跟踪自己的活动菜单；不借用可能残留的 currentEvent 长期保留浮窗。光标离开后恢复关闭，关闭父窗口或切换板块清理活动。没有新增常驻轮询。

## 验证与已有缓存边界

有限验证提取本机已安装 Codex 的纯文本标记判断函数，用合成文字执行：旧结构复现相同 TypeError，经过实际发送器构造的新结构正常返回。没有执行完整厂商脚本、连接模型或向真实任务发送测试文字。

回归覆盖真实分帧后的输入结构、中文及非 BMP 字符、原文与调用方对象不变、上下文注入拒绝，以及已提交但未确认不重试。原生预览契约涵盖移入、移出、父窗口、菜单、选文、滚动、旧回调和各类任务目标。

安装新版本会修正后续发送，不会直接改写 Codex 进程里已有的坏缓存。原生 load-complete-history 对完整历史直接返回缓存，不能作为强制重建方法。此处没有压缩、编辑、归档或重发已有任务，也没有强制重启 Codex。

实际原生界面的直接点击受当前电脑工具访问限制，无法代为点击 Codex 的重试；读取与导航可通过既有 Codex 工具进行。旧错误页是否恢复必须与新发送格式和本工具界面验证分开记录，不能仅凭后台任务完成或测试通过声称已恢复。
