# 0.28.2：主线程卡顿与后续功能的性能约束

2026-10-29，本机安装版从 0.28.1（37）更新到 0.28.2（38）。

## 确认的原因

旧版短采样中，主线程 986 个样本有 697 个落在定时扫描、状态更新和刷新路径；`CueThreadFollowups.valid` 对每个 Unicode 标量重新构造字符集合，历史记录刷新又重复验证相同 ID。与此同时，每次状态变化都会重建整套快捷菜单和任务控件，未变化的悬浮对话还会重复解析 Markdown。后台采集器当时约 0.1% CPU，主要瓶颈在原生界面的主线程。

## 现场结果

| 观测 | 旧版 0.28.1 | 新版 0.28.2 |
| --- | ---: | ---: |
| 约 3 秒内的进程 CPU 时间 / 墙钟时间，单核口径 | 96.7% | 3.3% |
| 最近任务列表 | 打开 | 打开 |
| 工作台 | 未打开 | 同时打开 |
| 该采样点的 RSS | 258.5 MiB | 259.5 MiB |

这是同一台 Mac 的现场短采样；期间任务内容和窗口状态有变化，不是相同负载下的严格 A/B，也不是长期平均值。没有宣称内存下降。新版另一次 2 秒调用栈采样中，主线程 1730 个样本有 1689 个在事件循环等待；未再观察到重复构造字符集的热点。

隔离的同一新版进程里，12 行控件连续更新 30 次：强制重建路径耗时 642.83 ms，差量路径耗时 0.79 ms。差量路径重建次数为 0、行刷新次数为 0，保留原文档对象。这个小样本比较的是两条刷新路径，不代表整个 APP 的倍数提升。

最终包含隐藏晚结果缓存补丁的安装包另取 3 秒采样，CPU 为 17.0% 单核，工作台打开。安装产物 SHA-256 与最终构建一致；这次补充采样仍只反映当时现场负载。

最终版本又在 4 个对话窗口可见时取 6 秒稳态采样，CPU 为 4.7% 单核；这段时间新增长回调 0 次、列表重建 0 次。多个窗口开启阶段曾记录到最长约 375 ms 的回调，因此不宣称所有首次打开或内容变化的工作都已经小于 16 ms；可见窗口与新内容仍然有实际渲染成本。

## 实现

- 不变的 ID 规则、分组索引、标题排序键和图标复用；快捷菜单在真正打开时才生成。
- 列表将结构、数据和时钟分开：成员/排序/布局改变才重建；仅更新变化的可见行；秒钟跳动只改时间标签。
- 对话和浮窗在遮挡、最小化或退出页面时暂停主动读取；隐藏后晚到的正文只缓存，恢复时消费最新结果一次。未变化的内容跳过 Markdown、TextKit 与 WebKit 重复排版。
- 状态文件、事件目录与 JSON 读取放到受限的后台队列；相同快照直接复用。已领取的提醒在交付确认后才删除，中途退出可恢复。
- 统计页合并查询、缓存未变化的表格/热图，不因相同汇率结果再次触发全量查询。

## 后续功能如何约束

[性能架构合同](performance-architecture.md)规定统一调度器、稳定任务键、可见性、单次执行预算和关闭时取消。主线程预算是协作式的，不会抢占已经运行的回调；超过 16 ms 的回调会进入诊断计数。

每次 `scripts/build.sh` 自动运行隔离的结构回归检查。未变化的列表如果重建、调度器出现重复或无法取消的任务、隐藏工作仍执行、事件确认或快照缓存回归，构建会失败。时间数据留作诊断，不使用随硬件波动的绝对耗时阈值。对话、统计与提醒的既有原生检查继续保留。

本轮保留原配置、草稿与历史：安装前 482 条提醒事件 ID 安装后全部存在；使用列表时待续状态会正常变化。已核对安装包与构建产物二进制一致，36 个 Python 运行文件与源码一致，Codex 连接及人工批准监控恢复正常。

原始 CPU、调用栈及小样本 JSON 保存在本机忽略提交的 `build/` 中。本轮没有修改系统设置、退出 Codex、切换账号或扫描真实历史数据库。
