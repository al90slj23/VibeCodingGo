# 未载入对话的后台模型设置（0.34.4）

0.34.3 只向已载入对话的桌面 owner 设置参数，其他项目等待用户打开。0.34.4 补齐无需打开对话的后台持久化路径，保留独立置顶的进度窗口。

## 本机协议验证

已安装 CLI 的 `thread/settings/update` 只接受其已载入的对话，直接修改未载入历史会返回 `thread not found`。隔离合成对话复现了这一限制。原桌面 IPC 仅提供 owner 请求，没有后台取得未载入 owner 的方法。

通过已安装 CLI 的有限 stdio 配置进程，可以 `thread/read`（`includeTurns: false`）核对元数据，再 `thread/resume`（`excludeTurns: true`）载入配置；不发送任何输入或启动轮次。保存后关闭进程，使用全新进程再次读取持久化索引及配置，模型、推理强度、速度全部符合才确认成功。设置接口只允许这三个字段，不能写权限、工作目录、活动轮次、提示词、账号或原生所有权。

兼容性根据原生 CLI 生成的真实协议定义检查，缓存随二进制文件身份失效，不绑定构建号。不直接改写 Codex 安装包、授权文件、配置文件或数据库；历史索引仅作只读检查，实际设置由原生 API 保存。

## 运行保护和资源约束

- 已有桌面 owner 继续走原连接，不启动第二个配置者。
- 后台载入前两次非阻塞检查原生 `thread-writer-locks`；原生 resume 自身的独占锁处理检查后的竞争。已有写入者返回拒绝，不停止、接管或抢占它。归档、临时对话与子代理不自动恢复。
- 后台进程只有 initialize、元数据读取、无正文载入和模型设置四类 RPC；没有 turn/start、steer、interrupt、thread/stop、认证或 daemon 操作。
- 每次至多一项、一个低优先级原生子进程；写入进程退出后才启动核验进程。每项有二十秒绝对预算，响应有大小上限，退出超时仅清理自己创建的进程组。
- 连接或运行者暂不可用时保留后台待处理，沿用已有健康快照驱动，每次一项；退避从三十秒增加到十分钟。不新增轮询时钟或常驻服务。
- 提交后确认丢失保留待核验和准确的目标参数，不能当作未发送再次提交。重新核验不调用 settings/update。

## 已完成的真实验证

隔离原生测试确认：设置退出后仍可回读，原生索引和配置一致；已有 writer 拒绝第二次载入；有效权限维持只读，没有新增任务开始／完成事件，Tokens 为零。

实际未载入的历史对话通过后台路径保存其原有模型和强度，约 2.374 秒完成跨进程核验；原生索引的权限和 Tokens 保持不变。之后 Codex 官方 read_thread 仍显示 notLoaded；原先六个运行任务仍在运行。该耗时只是这一项实测，不代表所有历史对话。

已载入目标仍核对原 owner 的三份证据；未载入目标的结果明确标记 persisted_settings，不虚构原生窗口输入框或已打开状态。进度增加“后台载入配置”，临时排队不再要求用户逐个打开。

0.34.4 / build 53 已安装到 `/Applications/VibeCoding Go.app`，原生二进制与全部 50 个 Python 模块一致，四项用户配置及提醒／待续 ID 无丢失。1,070 项后端测试通过，包含安装的 mise、Hurl、lnav 及隔离原生 CLI；39 项模型设置检查、315 项页面生命周期和 183 项浮窗检查通过。实际 App 界面选择未载入对话后显示“已确认 1 / 1”，进度框在处理和完成期间保持同一前台窗口。
