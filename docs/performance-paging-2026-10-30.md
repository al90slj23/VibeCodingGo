# 0.29.1 精确局部分页与快照编码优化（2026-10-30）

## 完成范围

版本 0.29.1 / build 42 已构建并安装到 `/Applications/VibeCoding Go.app`。这轮消除实际重复计算，保持原账本、Decimal 定价、未定价判断和时间语义；没有用近似 Token 数、延迟真实数据或时间 TTL 换速度。

1. **统计翻页按精确版本读取局部结果**。原先 `tableOnly` 只改变 loading 文案，后台仍构建全年日历、趋势、供应商分组、筛选目录和全量费用。现在只有同一 WAL 快照的账本身份、变更 generation、筛选、精确时间边界、价格来源、汇率、同步状态均匹配时，返回当前日志页和当前费用调度 metadata。Native 合并已验证的完整概览，只更新列表与分页。条件不成立就返回完整结果；无基准、未知协议、损坏回包有界地修复。
2. **快照签名复用已有精确编码**。每条明细用于身份判断的 canonical JSON 不再被总签名重复编码。组合签名保留类型域、ID 和 UInt64 长度定界，保留任务数组顺序；没有使用可能把 Bool 和 Int 混同的字典相等判断，也没有使用短 hash 代替字段身份。模型、自然过期、侧聊、恢复状态和未来未知字段继续参与变化判断。
3. **任务列表单一刷新入口**。同一 watcher 更新原先会经 `refreshMenu → updateStatusPopover → updateEmbeddedTasks` 和 `updateHealth` 再次走嵌入列表；常见可见状态下从 2–3 次遍历收敛为 1 次。连接变化导致工作台重建属于单独生命周期操作。新增 `updates_received` 计数，区分没有写控件和没有做重复遍历。
4. **持续门禁**。构建增加条件分页精度测试，并验证快照特征相同、重复明细编码为零和编码字节下降。未来板块沿用统一资源调度、按需引擎和有界报告，不增加各自的常驻轮询。

## 固定输入测量

测量使用临时目录里的 24,000 条合成账本、每页 50 条、369 个日历日期和 400 个趋势点。两次 warmup 后取 7 次中位数。数据不来自真实账号或会话，普通查询不联网。

| 范围 | 完整查询 | 条件分页 |
|---|---:|---:|
| 进程内查询与 JSON 编码 wall | 21.158 ms | 2.167 ms |
| 同范围 CPU | 20.906 ms | 2.141 ms |
| 响应 UTF-8 大小 | 342,090 bytes | 43,847 bytes |
| 全新 Python 进程端到端 wall | 237.286 ms | 226.601 ms |

进程内计算约缩短 90%，响应约减少 87%；新进程端到端只改善约 4.5%，启动与冷导入成本仍明显。不能据此宣称完整 App 或所有翻页都加速十倍。

另外对 0.29.0 的 Git 源码 `1d94c46` 在独立进程执行完整查询，新版分别合并第 1、2、17 页，逐字段完全一致：24,000 条请求、11,063,884 Tokens，所有金额、未定价标记、分组、日期、过滤目录和日志字段一致。原默认 CLI 返回格式不变，协议为显式 opt-in。

8 条长 Unicode 对话明细 × 16 次整数遥测更新的快照测量：

| 范围 | 原总签名编码 | 复用明细编码 |
|---|---:|---:|
| 后台投影 wall | 104.71 ms | 75.78 ms |
| 再次编码长明细次数 | 128 | 0 |
| JSON 编码累计 bytes | 22,692,640 | 15,105,424 |

全特征输出与变化判断矩阵保持一致。JSON API 的总调用次数没有减少，减少的是长明细的二次编码及其字节量；不要将其写成“所有序列化调用归零”。

## 边界与下一层成本

冷启动、筛选/账本/价格变化会完整重算；精确滚动范围的下界每次移动也会使概览失效。任意深页依然使用原来的 OFFSET SQL，未伪装成常数时间。全新 Python 采集进程仍有固定启动成本，若下一轮继续压低交互延迟，应先量化并设计可恢复的只读常驻查询服务，而不是简单扩大缓存存活时间。主线程空闲样本及启动以来峰值不能互相替代。

原始证据位于本地忽略的 `build/`：`vcgo-conditional-page-benchmark.json`、`vcgo-0.29.1-old-reference-check.json`、`vcgo-ui-performance.json`、`vcgo-0.29.1-python-tests.log`、`vcgo-0.29.1-native-checks.json`、`vcgo-0.29.1-installed-evidence.json`。报告公开保留方法和数值，用户数据与原始诊断不上传。
