# 工程工具自动更新与兼容维护（2026-10-30）

VibeCoding Go 0.31.0 / build 46 将工具设置加入同一工作台的第四个二级标签。mise、Hurl、lnav 共用一套版本与维护机制；执行页保持原有按需运行方式。

## 设置与可见状态

三张固定卡显示安装版本、官方最新稳定版、检查/更新/兼容验证时间、实际路径与原因。默认自动检查 24 小时，支持 6–168 整小时配置；界面提供 6/12/24/72/168 小时及关闭开关。设置写入私有文件并返回权威读回，手动检查在自动开关关闭时仍可执行。

打开页面只读取少量本地元数据，不读取整份二进制、不检查网络和运行兼容测试。后台完成时直接向已创建页面交回结果，隐藏时缓存；再次可见才应用。页面没有新增定时器。配置和维护状态分别带 config_revision / state_revision，较早状态回包不能覆盖新设置或已完成更新。

## 调度与资源

应用启动至少延后两分钟才考虑维护。既有 CueActivityScheduler 只比较内存中的到期时间、单飞状态和通道占用；未到期不启动 Python，不每分钟读取 JSON。到期且工程任务、历史维护空闲时才派发一个 maintenance 工作，进程使用后台 QoS；聊天、状态和工程执行的保留通道继续独立。

后台读取持久检查时间和失败退避，再次判断自动开关与到期。全程总预算 145 秒，原生进程 180 秒终止兜底；子进程有执行、输入、双管道输出上限并清理自身进程组。网络失败和不兼容指数退避 5 分钟至 6 小时。已通过验证而等待切换的候选会复用，不重复下载或验证。

## 官方来源和验证

来源固定为 jdx/mise、Orange-OpenSource/hurl、tstack/lnav。只接受明确版本标签、唯一的 macOS arm64 安装包、预期官方下载身份、大小及 SHA-256 摘要。拒绝预发布、版本回退、任意自定义命令和未知下载源；不获取 GitHub 或 Codex 授权。

GitHub latest 不是版本号排序，因此仍进行版本比较；发布资产的 digest 用作下载前的可信摘要，再核对实际文件。[官方 latest 接口](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[资产接口](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)。

候选先在私有临时配置目录中验证：

- Mach-O arm64 可执行架构、实际版本。
- mise：禁用联网、安装与项目配置，读取三种工具库存的 JSON。
- Hurl：只访问 loopback 合成服务，验证请求、成功断言、失败断言和报告格式。
- lnav：对合成日志执行固定 headless SQL，验证来源、时间和错误级别。

这些测试覆盖当前适配器实际使用的接口，不能承诺识别任意未来语义变化。破坏性接口、缺失安装包或摘要时保留可用旧版，在设置显示原因并自动复查；不执行尚未验证的新版本。

## 并发、保留与恢复

工程 CLI 持共享使用锁贯穿解析与执行。更新在锁外下载、解包、哈希和测试，只在短暂提交稳定链接与清单时尝试独占锁；忙碌则延期。初始安装入口和自动维护共用安装锁，且初始固定版本不会降级后来自动安装的已验证新版本。

自动维护取得进程锁后重新读取配置和状态，避免等待期间另一进程的提交导致状态版本回退。发布时再次核对当前清单、取消、总时限及自动开关；保存关闭后，尚未发布的自动候选不再启用。发布失败恢复原入口。强制退出留下的检查中状态会显示已中断，并在后续到期检查恢复。

提醒、用量、草稿和账号授权不参与工具更新。当前清单只关联上一可用版本；旧版本目录暂时保留，不自动清理磁盘。这次没有增加工具守护服务或重新启动 App 的更新步骤。
