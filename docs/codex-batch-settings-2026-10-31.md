# 模型设置、后台待处理与进度核验（0.34.3）

后续 0.34.4 已补齐无需打开未载入对话的[后台配置路径](background-model-settings-2026-10-31.md)。本文保留 0.34.3 的核验修复记录。

本次处理批量配置后原生模型仍不一致、缺少进度，以及配置时跳转 Codex 和进度框被遮挡的问题。

## 已确认的原因

原绿色提示只证明控制通道可达，不代表选中对话全部就绪。未载入项会失败；固定 85–90 秒的批次预算还会让大批次尾部超时。旧窗口等待整个进程退出才读取结果，中途看不到实际进展。

旧核验先读原生模型设置，再用 `latestThreadSettings` 覆盖它，可能掩盖原生回读与保存值的冲突；输入框使用的 `latestCollaborationMode.settings` 也未单独比对。这是隔离测试可复现的假确认缺口。旧版未保存用户原批次的完整逐项结果，不能据此断言原先 11 项都由同一个原因失败。

早期修订尝试通过对话 URL 打开未就绪项。Codex 的该入口会唤起主窗口并切换对话，是跳转的直接原因。0.34.3 删除了设置流程中的自动打开入口。

## 最终行为

- 列表入口为“模型设置”，选中后为“设置模型 (N)”，退出为“取消选择”。参数分为模型、推理强度、速度档位，均可保持原设置。
- 进度框作为独立浮动窗口置顶，失去应用焦点时不隐藏。主工作台保持原窗口层级；关闭进度框可让批次继续后台处理，重新进入入口复用运行中的窗口。
- 设置流程只向已有原生 owner 更新后续轮次参数，不导航、不恢复线程、不发送聊天内容、不启动或中断任务，不改变权限。未就绪项持久保存为“后台待处理”，可取消；等 Codex 自身载入后自动应用。排队不计为已生效。
- 只有原生专用回读、保存设置、输入框模型／强度均匹配，才显示“已确认”。三份证据分别比对，保存值不能覆盖原生冲突。速度读取独立保存档位；原生临时速度覆盖仍受已有共享接口边界限制。
- 逐项输出有界 JSON Lines，即时显示读取、写入、回读和计数。进度到达末尾表示本批项目已处理，另列已确认、后台待处理、待核验及未生效数量。
- 未生效项可单独重试；已提交而未确认的项目只读重新核验，不自动重发。连接自动或手动刷新均保留已有结果及未提交参数。

## 后台队列与资源约束

`codex-model-queue.json` 以 0600 保存明确提交的模型配置元数据，不保存对话正文。后台执行由既有健康快照驱动，只有观察到就绪 owner 才启动有限进程，不增加轮询时钟或常驻子进程。队列优先查询有界 ID，较大队列轮转，原有活动对话继续优先；状态读取沿用原有订阅预算。

单次后台处理一个项目，具有八秒绝对预算，与前台配置共享采集槽和批次锁。前台繁忙或连接暂不可用时退避。写入前先持久记录 `submitting`；崩溃、断线或确认丢失后保留待核验状态，不盲目再次提交。同一对话的新明确配置替代旧排队请求；取消只匹配该次请求标识。队列完成后合并完整结果，不能用一个项目的响应覆盖其他待处理项。

`codex-batch-result.json` 保存最近一批的进度及结果，不重放操作。所有 I/O 和解析位于既有后台队列，数据均有大小上限；没有新增对话全文扫描。设置流程不将对话算作已读，不清除通知角标。
