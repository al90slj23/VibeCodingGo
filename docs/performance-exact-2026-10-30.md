# 0.29.0：精确统计与响应架构优化

2026-10-30。此轮以既有 0.28.4 为基线；保留提醒唯一行、未查看角标、模型/速度只读校验和自动重连。

## 改变了哪些工作

- **统计聚合**：重复翻页不再重复全表聚合。派生数值按 SQLite 身份、事务 generation、明确的数据水位及 SQL 参数复用，支持独立 CLI 进程。每次新增、更正或删除请求、详情或归档数据都失效；缺少触发器或损坏缓存回到原 SQL。日志页和同步状态仍从同一 WAL 快照实时读取。
- **费用计算**：长期 watcher 复用未变的精确成本核；同一次统计内部复用相同请求分组的 Decimal 行成本。分组相加顺序、96 位 Decimal 上下文、币种、价格来源和舍入规则不变。价格优先级、汇率、到期状态依然按当前输入处理。
- **界面状态**：watcher 投影移到 utility 队列，单飞、只提交最新的完整状态。长正文与数值遥测分别复用，Token 或模型验证时间变化不再反复清洗 Unicode 正文。提交前重核 heartbeat、模型及侧聊到期状态。
- **资源准入**：查询、轻量状态、用户发送、长同步、网络和批量控制分开限制并发。共享历史读取默认最多 2 个；状态与发送各有独立槽位。窗口关闭会取消该窗口尚未执行的查询，已提交写操作不合并、不自动重发。
- **格式与内存**：精确数字、金额及时间格式器按线程复用；每项缓存和响应大小都有上限。控制响应改为边读边限制内存，超限返回失败，不能截断后当作完整成功。

## 固定隔离测量

| 样本与范围 | 基线 | 优化后 | 精确校验 |
| --- | ---: | ---: | --- |
| 64 个任务、192 条账本、1000 个模型价格，预热后连续 12 次刷新 | 75.78 ms | 16.86 ms | 完整输出逐项相同；重复成本折叠 1536 → 0 |
| 同一长 Unicode 正文、16 次整数遥测变化 | 17.39 ms | 5.09 ms | 校验和相同；正文解析 16 → 1 |
| 独立 24000 条请求、400 日、12 模型，完整统计/分页，串行新 CLI 进程的 3 次中位数 | 105.42 ms | 57.59 ms | 三页全部字段与旧版一致 |
| 上一项的进程 CPU 中位数 | 100.30 ms | 54.76 ms | 相同查询与数据 |

另一个 30000 请求加 3000 详情的隔离样本：全 SQL 查询约 54.19 ms，预热后的聚合复用约 3.98 ms；下一页、时钟前进 1 秒约 3.51 ms，完整结果相同。此样本冷查询约 56.16 ms，首次计算仍需读真值，不宣称冷查询一定更快。不同维度基数、缓存命中和费用分组会产生不同收益；这些是本机的小样本测量，不能当作所有数据规模的倍数承诺。

单次费用装饰的另一隔离样本包含 400 日、12 个模型、4800 个日分组；3 次中位墙钟约 46.06 → 31.23 ms，CPU 45.14 → 30.58 ms，完整输出和桶顺序一致。复用仅在同一次固定价目/汇率处理中存在，不能跨价格更新沿用。

精确缓存不按模糊时间窗口取整：滚动日期下界保持原值；只在请求和归档记录集合都不变时共享时间上界。状态为 unknown/partial/stale 的结果不会被缓存成新鲜完整状态；本轮和历史用量仍为两个范围，不能重复相加。

## 验证与维护

809 项后端测试通过；原生 372 项任务/提醒/投影检查、287 项统计检查、34 项金额检查、12 项排版检查、15 项菜单栏检查、10 项同步计划检查通过。构建自动核对 collector 准入、取消隔离、latest-only 投影、数字/布尔隔离、时间到期及精确输出校验和。

本轮没有真实历史重扫或旧故障压力复现。原始数值 fixture 和测量保存在本机忽略提交的 build/。新派生缓存为私有文件，可丢弃后按 SQL 重建；没有改写账本里的真实请求、源 token 或历史金额。

[后续模块性能合同](performance-architecture.md)要求每个新功能声明资源通道、真值来源、失效事件、时间边界和关闭取消规则。app-status.json 中包含 collectors 和 watcher_projection 的排队、复用、后台投影及主线程提交计数，watcher-state.json 记录任务成本缓存命中。这样后续排查可以定位具体层级，而不只看整机 CPU。
