# 工程工具（0.30.0）

[实现、测试与资源验收记录](engineering-release-2026-10-30.md)

主面板新增「工程工具」一级标签，二级标签为「环境体检 / 接口调试 / 日志诊断」。三页复用同一个原生控制器、视图和工作台，不另开功能窗口；文件选择使用工作台的附属选择框。菜单也提供这三个入口。

## 环境体检

1. 选择项目文件夹，也可输入绝对路径。
2. 点击「运行体检」。显示本机实际工具路径、版本、项目声明、匹配或待核对状态。
3. 切换标签保留本次输入和报告；再次点击才重新读取。

只读取固定的版本声明文件，如 `package.json`、`.nvmrc`、`.node-version`、`.python-version`、`.tool-versions`、`mise.toml`、`pyproject.toml`、`go.mod`。每个文件最多 128 KiB；不执行项目脚本、不读取 `.env` 值、不安装或激活工具。

支持明确的版本、主/次版本、比较范围以及常用 `^`、`~`、`||` 约束；复杂或无法核对的约束显示未知，不把未知当通过。省略版本段的 `>` / `<=` 在 npm 与 Python 等生态的展开规则不同，首版保留待核对；已找到但版本探测超时的工具显示“已找到，版本未核实”。体检反映 GUI 进程可发现的 PATH/常用目录版本，不冒充交互终端里已经激活的 nvm、mise 或虚拟环境。

可选 [mise](https://github.com/jdx/mise)（MIT）通过 `--no-config ls --installed --json <tool>` 补充库存信息，禁用联网和自动安装；库存不是当前项目的激活版本。未安装 mise 时，静态声明和本机版本体检仍可用。[官方 CLI 说明](https://mise.jdx.dev/cli/ls.html)。

## 接口调试

单条请求默认 GET，可选 POST、PUT、PATCH、DELETE、HEAD、OPTIONS。填写 HTTP/HTTPS 地址、请求头和正文，核对按钮上的方法后点击发送。支持 localhost 与内网目标，复用已有环境代理、macOS 系统代理和 PAC 规则。代理失败不偷偷改为直连。

单请求复用系统 curl。请求 URL、头和正文通过 stdin 配置传入，不放在进程参数里；不自动重试，不自动跟随重定向。4xx/5xx 保留真实状态并显示失败，TLS/连接错误与业务响应分开。显示状态码、耗时、响应大小、脱敏请求信息、响应头及正文预览。JSON 大整数和数值 literal 保留原值，不能因展示而舍入。

边界：超时 1–30 秒、请求头 32 KiB、请求正文 128 KiB、响应传输 256 KiB、正文预览 64 KiB。超过上限明确显示截断；取消后不自动重新发送，服务端可能已接收原请求。

集合模式可选择 `.hurl` 文件，再点击「执行集合」。可选 [Hurl](https://github.com/Orange-OpenSource/hurl)（Apache-2.0）实际执行请求和断言；未安装时集合模式显示安装说明，普通请求仍可用。[官方安装说明](https://hurl.dev/docs/installation.html)。

首版集合限制为 128 KiB、1–50 个固定 HTTP/HTTPS 目标，支持请求、断言和捕获；拒绝外部文件读写、动态目标、循环、自动重试或跳转等配置。集合目标适用不同代理/PAC 路径时要求拆分，不错误地给全部请求套同一代理。总运行时间和输出都有限制。Hurl 用私有空配置目录执行，防止隐含全局配置添加请求头或输出文件。

## 日志诊断

1. 选择 1–5 个普通日志文件。
2. 可填原文筛选文字、选择全部/错误/警告、选择最多 200/500/1000 行。
3. 点击「读取日志」。需要更新时再点击，不常驻跟踪文件。

每文件只读最多 512 KiB 尾部，总计最多 2 MiB；不扫描整个文件夹，也不为计算绝对行号重扫前文。截取后的相对位置显示「尾部第 N 行」。文件轮换、读取过程中变化、截断、不可读和未知时间分别标注；原文搜索是字面匹配，不执行正则或 SQL。

可选 [lnav](https://github.com/tstack/lnav)（BSD-2-Clause）对有界、已脱敏的临时快照执行固定 headless SQL，补充其识别的时间和级别，保留原生未识别行。临时目录只供当前进程访问，正常退出及可处理的取消会清理。未安装或不兼容时继续提供原生有界尾读，报告标明实际引擎。[官方 headless/SQL 功能](https://lnav.org/features)。

## 数据与资源边界

- 输入、原生草稿和结果缓存只在本次 App 内存中保留，不写成历史记录。lnav 的有界脱敏快照和工具空配置使用私有临时目录并清理；不把“没有持久历史”误写成所有处理都完全不经过磁盘。
- 报告对常见 Authorization、Cookie、Set-Cookie、Token、密码与私钥块脱敏。未知格式仍可能包含敏感内容，复制分享前应检查；不宣称能识别任意格式里的全部秘密。
- 页面构造、两级标签切换、文件选择和窗口恢复均不启动检测。只有运行按钮创建客户端。没有新增轮询、守护进程、浏览器或全盘索引。
- 工程工具共用一个有限后台槽，不占用消息发送、状态查询、用量同步的保留槽。切页、关闭或停止会取消自身排队与运行操作，迟到结果不能写入新页面。工程进程拒绝退出时有单独的有界终止兜底，不改变聊天发送的取消规则。
- 工具使用 argv、`shell=False`、双管道排空、执行时限和输出上限；取消会清理自身子进程组。版本探测禁用 Corepack 联网，避免自动下载包管理器。
- 报告在 utility 队列格式化，主线程只显示有界文本，整个界面报告上限 96 KiB。隐藏/最小化/完全遮挡时不应用回包 TextKit；恢复可见时消费缓存，不重新执行请求。
- 可选工具只在运行时探测和调用，App 不打包另一套 Electron、Node 或常驻工具服务；本轮没有全局安装 mise/Hurl/lnav。安装官方 CLI 后下次运行会自动发现，无需更新 App。

诊断 `performance.engineering` 只记录选中工具、显式运行次数、客户端/取消/报告计数和可见性，不包含 URL、请求头、正文或日志内容。

## 验证方法

构建会执行工程工具离线测试和原生性能门禁。原生 fixture 检查零自动运行、标签复用、窗口尺寸、草稿、取消、隐藏回包、错误协议和文本上限；后端测试使用临时项目、合成日志和本机 HTTP 服务。真实官方 mise、Hurl、lnav 的适配另在临时目录、隔离 HOME 和合成输入上核对，不读取用户真实日志或凭据。

可以使用 `--engineering-self-test` 运行原生检查，或 `--capture-engineering-fixture <path> --engineering-kind environment|api|logs` 生成离线界面样例。Python 模块为 `vibecue.engineering_tools`，子命令 `environment`、`api`、`logs`、`capabilities`，参数通过有界 JSON stdin 提供。可选 Hurl 真实回归通过 `VIBECUE_TEST_HURL` 指定已验证工具，不要求普通用户为运行全部基础功能安装额外依赖。
