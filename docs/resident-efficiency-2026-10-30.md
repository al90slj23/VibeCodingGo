# VibeCoding Go 0.34.0 常驻效率

目标是让辅助工具闲置时少做工作，显示时及时响应。保留已有提醒强度、动画目标、用量口径、同步设置、草稿和恢复记录。

## 收到事件才处理

- 两个可取消的内核目录订阅分别监控提醒收件箱与设置请求。心跳、台账和状态文件的日常写入不再推动主线程读收件箱。
- 原有健康时钟每 2 秒补查目录身份并兜底读取；目录替换可自动重挂，提醒仍由持久 spool 保存。
- 正在读取时收到的通知保留一次补读；认领事件只在主线程交付后确认，不提前删除。
- 空收件箱不再反复写 app-status。诊断保持自己的 5 秒节奏和实际状态变化写入。
- 模型订阅保留原优先级与 256 项成员边界，同一组只改变活动顺序时不再重写目标文件。

## 首次打开才创建界面

- 后台历史同步与定价保留原有调度，只拥有数值状态；统计窗口、筛选、表格、热图与分页在明确显示时创建一次。
- 隐藏或遮挡的统计页面停止显示查询与汇率显示工作；已到达的数值快照留待再次显示。
- 账号额度继续按原监控频率读取。隐藏时延迟卡片构建；同样数据、尺寸与有效期状态复用原卡片。
- 恢复显示时重新检查有效期和重置边界，过时额度显示为上次数据，不误称实时。

## 绘制与监听

- GPU 每个边缘视图仅构造一次静态参数模板；逐帧只更新动态字段。参数与参考实现逐元素核对，覆盖全部 59 个目录样式。
- 完全相同的参数与绘制尺寸跳过重复提交；淡入淡出仍分别计算。窗口遮挡暂停帧门控，恢复后呈现最新帧。
- 播放完成释放音频播放器及解码缓冲；音量为零不准备不可听的音频。
- 对话监听根据订阅、发现、所有者检查与批准结算的真实截止时间等待，空闲最长等 1 秒；socket 数据或 EOF 仍立即唤醒。原批准结算短期限不变。
- watcher JSON 紧凑编码保留原字段、整数、转义与大小保护。代表性数值快照从 336,040 字节降为 246,597 字节，减少约 26.6%。不降低会话监控、心跳或恢复记录保存频率。

## 本机观察

30 秒有限采样只读取本应用、watcher 的 CPU/RSS 和数值诊断，不读取提示词或账号凭证，不产生提醒和请求。

| 观察项 | 结果 |
| --- | --- |
| 冷启动后台统计 | 已启动，统计界面创建 0 次，显示查询 0 次 |
| 0.34.0 无提醒区间原生 CPU | 7 个区间，中位 0.99%，峰值 1.98% |
| 本轮原生进程峰值 RSS | 约 103 MiB |
| 内核订阅 | 2 个，通知到达后即时读取 |
| 健康补查 | 稳定目录复用订阅，实际重挂与检查次数分别计数 |

这段采样包含正在运行的真实对话，也包含真实提醒。全段 CPU 中位 8.38% 混合了提醒绘制，不能视为闲置占用；剔除提醒及切换边界后才得到上述 7 个区间。无提醒端点仍可能漏掉两个采样点之间的极短提醒。

旧 0.33.0 另一段 30 秒观察为原生 CPU 中位 1.5%、峰值 RSS 约 217 MiB，但当时面板已打开、运行任务与缓存状态也不同。因此这些是现场观察，不是严格相同负载的速度或内存改善比例。后台监听与精确数据处理仍有合理开销，不承诺零占用。

采样工具：scripts/sample-resident-performance.py --duration 30 --output build/resident-runtime.json。输出不应提交到公开仓库，用户的数值用量与运行状态只留本地。

## 验证边界

Python 回归、真实 GPU 样式检查与原生性能契约分别运行。构建额外执行统计和账号额度页面的独立隔离契约，覆盖懒初始化、隐藏更新、有效期、分页、筛选和滚动范围。

测试发现并修复两类验证问题：渲染 fixture 必须明确装配懒加载页面；Cocoa 的 isWindowLoaded 不能证明未分配控件，改为检查实际窗口引用和组件构造次数。原有布局断言全部保留。到期边界的 watcher 合成使用同一个明确的时间基准，避免参考值和合成值跨秒。

本次构建与安装验证：

- Python 完整回归 1,031 项通过，包含托管工程工具的真实引擎测试。
- 原生核心性能契约 161 项通过；统计和账号页面独立契约 315 项通过。
- 真实 GPU 验证 15 项通过，涵盖全部 59 个样式；后续仅修改了时间基准、界面 fixture 装配和目录诊断计数，未改变 GPU 实现。
- /Applications/VibeCoding Go.app 为 0.34.0 / build 49，原生二进制与构建产物一致，48 个 Python 文件与安装 runtime 一致。
- 安装前的提醒 ID 全部保留，设置、窗口位置、草稿、待续记录与用量显示配置五份文件哈希保持一致。Codex 自动连接恢复为 connected。
- 实际工作台通过两级标签打开统计，首次构建为 1 次、39 组控件；真实历史数据加载成功，下一页仅切到请求日志第 2 页，分页仍属于列表。
- 账号页面通过既有共享授权显示已有账号额度，无切换账号或重新授权。切回工作台后观察 30 秒，显示查询保持 3 次、快照应用保持 2 次，均未增长；重新进入保留第 2 页及完整概览，随后将页码恢复为第 1 页。

最终安装后、已打开统计与账号页面再切回工作台的 30 秒观察：原生 CPU 中位 0.99%、峰值 2.49%，峰值 RSS 约 138 MiB；watcher CPU 中位 2.49%、峰值 12.07%，峰值 RSS 约 55 MiB。该段 15 个区间均无提醒显示，仍有真实对话在运行。调度主线程最长回调约 1.14 ms，slow_callbacks 为 0。目录健康检查从 65 到 80，真实订阅构造保持 2 次，没有重复挂载。

以上为两类进程分别记录的现场值，不代表整个 Mac 的 CPU、内存或其他程序占用，也不是不同任务量下的严格基准。
