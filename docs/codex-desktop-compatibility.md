# Codex 桌面更新后的自动兼容

2026-10-30，修复版本 0.28.3（39）。

## 本次根因

旧适配器将 Codex 桌面版本与构建号硬编码为唯一白名单 `26.1021.31345 / 21828`。本机 Codex 已更新为 `26.1023.51421 / 22530`，因此 VibeCoding Go 在握手前主动拒绝了连接，显示“窗口回复协议尚未核对，请更新”。这不是 GPT 模型升级导致的接口错误。

只读核对新版安装资源后，回复、模型设置、对话归属和状态订阅的关键方法版本均与之前相同。使用修复后的源码已完成真实 IPC 握手、归属发现及运行状态读取；读回模型、强度和标准速度，未发送文字、改变设置或重新授权。

## 新的判断方式

1. 保留私有 socket 权限、同用户进程、实际应用路径及 `com.openai.codex` 身份验证。
2. 从已验证应用自身的 `app.asar` 读取静态方法版本表，不执行 JavaScript。支持带哈希的文件名及有限主进程构建目录，不扫描对话或凭据。
3. 把本工具实现的方法版本逐项与实际安装版本比较；构建号、应用版本和新增模型不再作为连接开关。未版本化的初始化使用只读 v0 握手并要求有效的客户端 ID 回执。
4. 回复、批量设置与注意力订阅分开计算能力，缺少或改变单个方法时，不冒充该功能可用。先检查契约，再允许对应操作；从不通过试发消息、试切模型或试批准来探测。
5. 应用资源替换后按 inode、大小及纳秒修改时间自动重新解析。每次新连接重新校验身份与契约；兼容性检查失败也保留低频只读恢复检查，不要求用户反复点击接通。

资源解析有界：12 MiB 索引、单脚本 4 MiB、总脚本 32 MiB、最多 512 项；仅保留 8 项进程内缓存，成功与失败均缓存，资源变化即失效，失败还会在 30 秒后重新检查以恢复临时文件访问错误。本机首次约 81–165 ms，命中缓存约 0.10 ms；单次短测，不作为跨机器保证。

## 行为边界

真正改变的方法版本不会被猜测兼容；受影响操作保持禁用，界面说明后台自动检查，诊断保留具体方法。协议格式完全改写仍可能需要适配，但普通客户端构建更新不再需要发布 VibeCoding Go。

只读状态可以在新连接上重试。消息或设置一旦已经提交，确认丢失只标记未确认，绝不因兼容恢复自动重发。已有草稿和发送回执保留。

[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)提供公开客户端协议；本工具为了复用原生窗口的对话所有者，仍使用已安装桌面的内部 owner IPC。这里的契约检查不是对未来内部接口永远稳定的承诺。

## 验证

隔离测试覆盖新版构建不再拦截、方法级退化、未知流不订阅、身份/权限拒绝、静态资源损坏/冲突/边界、成功和失败缓存、资源替换重新核对、初始化及写操作回执与不重发。原生界面检查覆盖自动复查、无手动接通按钮、禁发和保留诊断。构建继续执行现有性能结构门禁。

本机真实只读状态验证同时确认 `connected=true`、`supported=true`、`can_send=true`（运行中对话），独立读取模型设置成功。读取结果写入本机忽略提交的 `build/vcgo-0.28.3-live-compatibility.json`，未将对话内容或账号信息写入文档。

最终安装核对：`/Applications/VibeCoding Go.app` 为 0.28.3（39），二进制与构建相同，全部 37 个 Python 运行文件与源码相同。780 项后端测试、339 项原生检查、12 项排版检查和性能结构构建门禁通过。旧悬停检查的固定短等待出现过一次时序失败，无代码变更的复查已全部通过。常驻监控恢复回复、批准提醒、批量设置三项能力；实际对话窗口显示“已接通，可发送到当前对话”。7 份本地配置/草稿等文件哈希未变，503 条原提醒事件 ID 全部保留。
